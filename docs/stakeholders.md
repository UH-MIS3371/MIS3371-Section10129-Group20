# Stakeholders

| Stakeholder | Role in the Transaction | What They Need |
|---|---|---|
| **Referring Provider** (physician, NP, clinician) | Initiates the referral; corrects it if returned | Fast submission, confirmation with a referral ID, current status, reason if declined |
| **Receiving Department Staff** (specialty clinic intake) | Reviews and decides — accept, reject, or request more info | Complete referral details, a review queue, a required reason field for rejections |
| **Referral Coordinator** | Monitors all referrals; follows up on incomplete or overdue ones | Visibility into Incomplete and overdue referrals, search by patient, ability to cancel with a reason |
| **Scheduling Staff** | Marks an accepted referral Scheduled, then Completed | A clear list of Accepted referrals ready to schedule |
| **Patient** | Subject of the referral (does not use the system directly) | Timely care and an accurate answer when they ask their provider or coordinator about status |
| **Clinic Administrator / Auditor** | Oversees the process | A traceable history of every status change, who made it, and when |
| **System Administrator** | Configures the system | Manage user roles and the service-to-department routing list |

**Primary stakeholders:** Referring Provider, Receiving Department Staff, Referral Coordinator, Patient.
**Secondary stakeholders:** Scheduling Staff, Clinic Administrator / Auditor, System Administrator.
